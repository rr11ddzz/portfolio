The question

Can claim information help classify the fraud_reported label, and how does class imbalance affect the result? The notebook explores an insurance-claims dataset using pandas, categorical encoding and scikit-learn models.

The strongest lesson is methodological: a model can appear accurate while missing nearly every positive case. The portfolio therefore explains the saved results and their limitations instead of presenting one accuracy figure as proof of a useful fraud detector.

The experimental workflow

  • Clean the working dataset and inspect relationships through exploratory plots.
  • Encode categorical variables; use a random forest to rank candidate features.
  • Train a logistic-regression model on a selected feature subset with an 80/20 train/test split.
  • Explore oversampling, undersampling and a regularized logistic-regression configuration.
  • Inspect classification reports and confusion matrices, including precision and recall for the positive class.

What is verified

The code, saved classification reports and confusion matrices were inspected. The published copy does not include the original cleaned CSV, and the analysis was not rerun for this update. Results describe the archived experiments only.

This is an exploratory learning project. The recall comparison highlights why the split, preprocessing and class distribution must be controlled before making performance claims.

A stronger evaluation design

  • Split once into training and untouched test data before learning transformations.
  • Fit encoders, feature selection and any resampling only within training folds.
  • Compare every model against a simple baseline on the same held-out data.
  • Report positive-class precision, recall and PR-AUC, with explicit decision-threshold trade-offs.
