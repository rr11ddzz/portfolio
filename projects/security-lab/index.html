Scope and environment

Investigate intentionally vulnerable training systems using a Kali Linux virtual machine and applications such as DVWA. The original coursework records discovery, network observations, web exercises and mitigation discussion.

This portfolio presents a curated technical case study rather than the full raw report. It represents academic lab work, not a commercial penetration test or an assessment of a live organisation.

A service banner is an observation, not proof that a vulnerability is exploitable. A clear report separates discovery results, demonstrated behaviour and broader risks discussed in the coursework.

Example finding: SQL injection in DVWA

The original screenshot shows a crafted input returning multiple seeded DVWA user records. Within this intentionally vulnerable application, that behaviour demonstrates input changing the intended query logic.

Finding elementInterpretation
ObservationSeveral demonstration records are returned from a single input.
ImpactAn application may disclose data outside the intended lookup.
Primary remediationUse parameterized queries so input is treated as data, supported by least-privilege database access.
Verification to performRepeat valid and invalid lookups after remediation and check that input cannot alter query structure.

The names shown belong to the training application’s seeded demonstration data. No real customer-data breach is claimed.

What is verified

The original report and selected screenshot have been reviewed. No fresh scans or exploitation were carried out for the portfolio. The document contains a mixture of practical evidence and explanatory discussion; this case study does not treat every described attack as a confirmed successful test.

Mitigations are recommendations from the investigation, not changes claimed to have been deployed.

What a stronger follow-up would include

  • A concise scope statement, repeatable lab setup and a finding register with evidence references.
  • Prioritization by demonstrated impact and exposure, rather than tool output alone.
  • Retesting after parameterized queries, restricted services and session-hardening changes.
  • A clear distinction between observed results, hypotheses and unresolved questions.
